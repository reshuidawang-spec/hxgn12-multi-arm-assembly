# 五臂协同

## 这是什么

五台 CR5A 机械臂在 CoppeliaSim 里协同装配一条电控箱产线：并行抓取 → 放箱 → PCB → 端子 → 模块 → 转运 → 锁付 → 分拣 → 回等待点，全程零碰撞。机械臂沿**预录路径**运动，段与段之间用**事件**接力。

```
R4/R5 先到等待点站位，R1/R2/R3 并行抓取（箱体/PCB/控制模块）
  ↓
R1 放箱 → R2 放PCB → R1 装端子（松开夹爪，端子落下安装）
  ↓
R3 放控制模块（同样松开落下）→ 成品显示、零件隐藏
  ↓
R3 搬运成品到检测区 → R4 锁付 → R5 分拣到GOOD传送带
  ↓
五臂回等待点，准备下一轮
```

## 我要做什么，用什么

### 演示五臂完整流程（终端）

```bash
cd ~/桌面/cr5_assembly_team && python3 scripts/coordinated_front.py
```

- 第一轮从 home 出发
- 上一轮已跑完（各臂在等待点）续跑：加 `--start-from-wait`

### 单独控制一台机械臂（写代码）

用 `ReplayController`（`robot_control/replay_controller.py`）：

```python
from sim_bridge.coppelia_client import SimBridge
from robot_control.replay_controller import ReplayController

bridge = SimBridge()
bridge.connect()                          # 场景已打开
ctl = ReplayController(bridge, "R3")      # R1~R5 任选

ctl.replay(ctl.load("r3_module_pick_descend"))   # 让R3沿某段路径走
ctl.replay(pts, reverse=True)                    # 反走（抓完抬升/放完退出）
ctl.gripper(0.080)                               # 夹爪开度
ctl.attach("CONTROL_MODULE_SUPPLY")              # 抓工件
ctl.detach(handle)                               # 放工件
```

单臂演示脚本（快速看效果）：`scripts/r1_demo_flow.py` ~ `scripts/r4_demo_flow.py`

### 接入团队 app / 调度系统（写代码）

用 `CoordinatedEngine`（`robot_control/coordinated_engine.py`）：

```python
from robot_control.coordinated_engine import CoordinatedEngine

engine = CoordinatedEngine()
engine.run_cycle()        # 触发一轮完整协调，阻塞至完成
engine.get_status()       # 查询是否在跑/最近结果
```

app 接入链路：app 下单 → `SimulationCellExecutor` → `CoordinatedEngine.run_cycle()` → 完成。app 里任意 A/B/C 订单点 START 即可。

> **两个入口是同一个流程**：`coordinated_front.py` 是命令行脚本，`CoordinatedEngine` 是它的类封装。终端操作用前者，程序集成用后者。

## 代码都放在哪

| 文件 | 干什么 |
|---|---|
| `robot_control/coordinated_engine.py` | 五臂协调引擎（app 接入、状态查询） |
| `robot_control/replay_controller.py` | 单臂回放控制器（预录路径驱动单臂） |
| `robot_control/simulation_executor.py` | app 接入层，`COORDINATED_CYCLE` 触发协调 |
| `scripts/coordinated_front.py` | 五臂协调执行脚本 |
| `scripts/r1_demo_flow.py` ~ `r4_demo_flow.py` | 单臂演示 |
| `scripts/replan_robot.py` | 按关键姿态重规划某臂全部段 |
| `data/captured_paths/r*_key_poses.json` | 各臂关键姿态 + 段定义（改姿态改这里） |
| `data/captured_paths/r*_<段名>.json` | 各段预录关节路径 |

> `robot_control/r1_motion.py ~ r5_motion.py` 是旧串行控制器，保留但新方案不用。

## 改路径怎么改

1. 改 `data/captured_paths/r3_key_poses.json` 里的姿态（抓取位/放置位/等待点等）
2. 重新生成路径：`python3 scripts/replan_robot.py r3`（换成对应臂）
3. 个别段 moveit 规划不了（姿态组合差异大）时，改用 simIK 逐点生成（参照 `r3_product_pick_descend` 的生成方式）

## 环境与注意

- 启动仿真：`~/CoppeliaSim/coppeliaSim.sh scenes/compact_cell.ttt`
- 重规划路径需要 move_group 在运行：`ros2 launch cr5_moveit dobot_moveit.launch.py`；规划报错先检查 move_group 进程
- 场景文件改动后要同步 `configs/scene_contract.yaml` 和 `robot_control/plans/*.json` 里的场景指纹
- 段与段衔接：相邻段首尾姿态必须一致（每段起点=定义起点、终点=定义终点），反走段终点是 app 位
