# 调度算法思路

当前测试使用“动态综合评分 + 滚动重调度”。

## 1. 固定工艺流程

单个产品内部工序不改变：

```text
R1 箱体上料
 -> R2 PCB 安装
 -> R3 控制模块安装
 -> R1 端子排安装
 -> R3 转移到检测平台
 -> CAMERA 相机检测
 -> NG：R5 直接缺陷品分拣
 -> OK：R4 锁付，再由 R5 良品分拣
```

## 2. 动态调度流程

```text
读取订单
 -> 拆分数量订单为单件订单
 -> 生成固定工序 DAG
 -> 找出当前可执行任务
 -> 检查资源和共享区域
 -> 对候选任务进行综合评分
 -> 执行最高分任务
 -> 相机检测后生成 OK / NG 后续分支
 -> 新订单或急单插入后重新评分
```

## 3. 评分因素

综合评分考虑：

- 订单优先级；
- 交期紧急程度；
- 延期风险；
- 等待时间老化；
- 剩余关键路径；
- R3 瓶颈资源；
- 检测平台共享区域；
- 检测后清台；
- 急单临期加分。

这不是强制 A/B/C 交叉排序，而是根据评分逻辑决定订单顺序。

## 4. 质量分支

- NG：相机检测后直接生成 R5 缺陷品分拣；
- OK：相机检测后先生成 R4 锁付，R4 完成后再生成 R5 良品分拣。

## 5. 指标

测试窗口和预览输出包含：

- Makespan；
- 冲突数；
- 急单响应时间；
- 急单完成时间；
- 加权延期；
- 检测平台平均驻留时间；
- 检测后平均等待清台时间。

## 6. A/B 换型插单逻辑

新增 A/B 换型演示流程用于验证“型号切换 + 插入订单”的场景：

```text
完成 5 台 A
 -> 插入 2 台 B
 -> 物料换型中
 -> B 型待装配物料就绪
 -> 完成 2 台 B
 -> 切回 A 型物料
 -> 完成剩余 A
```

调度算法仍然只改变订单/任务优先级，不改变单件产品内部工序。

换型过程不移动原始物料点位，而是在仿真脚本中动态创建 A/B 物料车标识，并通过信号显示：

```text
cell_material_state=changeover_A/B
cell_product_state=material_switching_A/B
```

换型等待时间由窗口中的“物料换型等待秒数”控制。

## 7. 质量评价逻辑

窗口中的 `AUTO次品数 / 100台` 用于设置质量评价比例。

- 显式选择 `OK` 或 `NG` 的订单按人工设置执行；
- 选择 `AUTO` 的订单按比例确定良品/次品；
- 结束后输出良品数量、次品数量、成功率和总用时。

评价文件：

```text
output/dynamic_order_evaluation.json
```
