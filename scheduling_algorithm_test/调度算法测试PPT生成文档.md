## 第1页｜项目困难与调度需求

### 页面标题

多机械臂混线装配的难点在于：动态订单与固定工艺必须同时满足

### 页面正文

在五机械臂电控箱装配场景中，调度问题并不是简单地对 A/B/C 订单进行排序，而是要在真实产线约束下处理多种耦合关系：

| 项目困难 | 具体表现 | 对调度算法的要求 |
|---|---|---|
| 工艺流程固定 | 每个产品必须依次完成上料、安装、检测、锁付/分拣 | 订单顺序可变，但单件产品内部工序不能改变 |
| 多资源共享 | 机械臂、装配夹具、检测平台、传送带存在占用冲突 | 调度时需要考虑机器人和共享区域是否可用 |
| 急单动态插入 | 仿真运行中可能新增急单 | 需要快速响应急单，但不能打断已执行工序 |
| 检测后质量分支 | 良品和不良品后续流程不同 | 检测后应动态生成 OK/NG 分支任务 |
| 检测平台易阻塞 | 产品检测完成后若不及时分拣，会影响后续订单 | 需要优先清理检测平台，提高流转效率 |

### 页面结论

因此，本项目的核心不是“让订单看起来交叉”，而是在工艺、资源和急单约束下，动态选择当前最合理的下一项任务。

### 建议图示

做一个“三重约束”图：

```text
固定工艺流程
      ↓
多机械臂资源冲突  →  动态调度问题
      ↑
急单插入与质量分支
```

### 讲解备注

这一页先把困难说清楚。可以强调你在测试中发现的问题：分拣不及时、检测后流程不清楚、颜色串色、订单插入后仿真状态需要同步。这些问题推动了后面的算法和系统设计。

## 第2页｜调度算法设计

### 页面标题

基于固定工序 DAG 与动态综合评分的滚动重调度算法

### 页面正文

为保证生产逻辑正确，系统首先将每个产品建模为固定工序 DAG：

```text
R1 箱体上料
 → R2 PCB 安装
 → R3 模块安装
 → R1 端子安装
 → R3 转移检测
 → CAMERA 相机检测
```

检测后根据质量结果生成分支：

```text
良品 OK：R4 锁付 → R5 良品分拣
不良 NG：跳过 R4 → R5 缺陷品分拣
```

在每个调度时刻，系统只从“前置工序已完成、资源可用”的候选任务中选择执行对象，并计算综合评分：

```text
Score =
优先级 + 交期紧急度 + 等待老化 + 延期风险
+ 检测后清台奖励 + 急单临期奖励
- 共享区域冲突惩罚
```

### 算法策略

- **固定工序 DAG**：从机制上避免跳步、倒序和重复工序；
- **动态综合评分**：根据优先级、交期、等待时间和资源状态决定下一任务；
- **滚动重调度**：新增订单或急单插入后，只重排未来候选任务；
- **质量分支调度**：相机检测后，良品进入 R4 锁付，不良品直接进入 R5 分拣；
- **清台优先机制**：对检测后锁付/分拣任务加权，减少检测平台阻塞。

### 页面结论

算法优化的是“订单之间的执行优先级”，而不是改变单个产品内部工艺路线，从而兼顾调度灵活性和生产真实性。

### 建议图示

左侧放固定工序 DAG，右侧放评分公式，下方放滚动重调度时间轴：

```text
已完成任务 | 正在执行任务 | 可重新排序的未来任务
```

### 讲解备注

这一页是核心算法页。可以说：算法并不是强制 A/B/C 交叉，而是在每个时刻根据评分逻辑选择最优任务，所以订单顺序是由评分结果自然产生的。

## 第3页｜系统实现与仿真验证

### 页面标题

构建“订单输入—调度计算—仿真联动—状态反馈”的闭环测试系统

### 页面正文

为了验证算法在真实仿真场景中的执行效果，项目搭建了动态调度测试系统：

```text
动态订单输入窗口
   ↓
订单 JSON 接口
   ↓
调度算法重新计算
   ↓
CoppeliaSim 五机械臂场景执行
   ↓
订单顺序、工序状态和产品颜色实时反馈
```

### 系统功能

- 支持 A/B/C 多型号订单输入；
- 支持运行过程中插入急单；
- 支持再次输入订单后同步重调度；
- 支持 2 倍速仿真演示；
- 使用颜色区分订单类型：A 型黄色、B 型绿色、C 型蓝色、急单红色；
- 在窗口中显示订单顺序、任务时间线、完成状态和关键指标。

### 验证指标

- 总完工时间 Makespan；
- 急单响应时间；
- 急单完成时间；
- 加权延期；
- 资源冲突次数；
- 检测后等待清台时间。

### 页面结论

该系统将抽象调度算法转化为可观察、可复现的仿真验证过程，能够直观检查急单响应、工序顺序、质量分支和资源占用是否合理。

### 建议图示

左侧放输入窗口截图，右侧放 CoppeliaSim 五机械臂场景截图，中间用 JSON 接口连接。底部放颜色图例：

```text
A=黄   B=绿   C=蓝   急单=红   已完成=灰
```

### 讲解备注

这一页说明最终落地形式。重点强调：系统 APP、场景和机械臂规划保持独立，调度测试模块通过接口联动仿真平台，方便后续替换或优化调度算法。
